# OneTrip Reality Check

ИИ-агент для планирования поездок, который не просто составляет маршрут, а **проверяет, насколько поездка реалистична, по карману и выполнима**.

> **Статус: MVP готов.** Работают разбор запроса, подбор транспорта и отеля, маршрут по дням, детерминированный Reality Check, автоматические исправления, Streamlit-интерфейс и оценка сценариев на тестовых фикстурах.
> Приложение использует реальные открытые данные (OpenStreetMap, Wikipedia, Open-Meteo) и сервис поиска **travel-search-ru**: кэш авиабилетов Aviasales, расписание поездов Tutu.ru и предложения отелей Level.Travel / Travelata без API-ключа. Travelpayouts остаётся запасным источником цен. Где данных нет, показываются **помеченные оценки проекта**.

Главная идея: **другие агенты составляют план, а мы проверяем, что он не развалится на месте.**

Проект сфокусирован на **поездках по России**: на первом экране — Москва, Санкт-Петербург, Казань, Сочи и Екатеринбург, а в мастере можно указать любой город.

## Идея

Пользователь пишет запрос обычным языком:

> «Хочу поехать в Казань на 4 дня в середине ноября. Бюджет — 60 000 рублей. Люблю архитектуру и кофе, не люблю толпы».

Агент:

1. разбирает запрос в структуру `TripRequest`, при нехватке данных задаёт один уточняющий вопрос;
2. строит маршрут «точка → точка»: сравнивает **самолёт, поезд и автобус**, подбирает отель и места;
3. строит маршрут по дням и считает стоимость, включая дорогу туда и обратно;
4. запускает **детерминированные проверки** и находит проблемы;
5. пытается исправить план и проверяет его снова;
6. честно показывает, что осталось нерешённым, и выгружает отчёт в Markdown.

## Важно про данные

Приложение никогда не выдаёт оценки за реальные цены. У каждого транспорта и отеля есть `price_kind` и `source`:

| Пометка | Что означает |
|---|---|
| `real` | цена из кэша travel-search-ru (Aviasales, Level.Travel, Travelata) или Travelpayouts. Это **не поиск в реальном времени**: данные могут отставать, а даты — не совпадать с запросом |
| `estimate` | оценка проекта по расстоянию и допущениям из `data/assumptions.json`, либо ориентировочная цена поезда из кэша Tutu.ru |

Внутренняя пометка `mock` осталась только в тестовых фикстурах; продукт её не выставляет.

- **Никакого скрапинга.** Приложение не парсит сайты Aviasales, Level.Travel и РЖД и не обходит их защиту. Используются только открытые API, партнёрский API Travelpayouts и открытый MCP-сервис travel-search-ru, который сам работает с официальными источниками.
- **Авиабилеты** приходят из кэша Aviasales через travel-search-ru: сервис отдаёт самый дешёвый вариант на дату и подписывает кэш возрастом до 48 часов. Время прилёта рассчитывается по длительности перелёта.
- **Поезда** приходят из кэша Tutu.ru через travel-search-ru только для маршрутов внутри одной страны. Цена ориентировочная, наличие мест не подтверждается. Для зарубежных направлений поезд не запрашивается, а оценивается проектом.
- **Отели** приходят из Level.Travel или Travelata через travel-search-ru. Цена — **за всех туристов и всё проживание**, а не за ночь; предложения живут около 20 минут. Без данных сервиса — кэш Hotellook по токену или оценка проекта (4 500 ₽ за ночь, рейтинг «нет данных»).
- **Расстояние отеля до центра и метро** сервис сообщает не всегда. Если расстояние неизвестно, приложение пишет «нет данных» и не считает такой отель лучшим и не создаёт ложную проблему.
- **Погода**: прогноз Open-Meteo доступен примерно на 16 дней вперёд. Для более далёких дат показывается архив за те же даты прошлого года и подписывается как «типичная погода, не прогноз».
- **Места** из Wikipedia GeoSearch — реальные названия и координаты, но без рейтинга, часов работы и стоимости входа. В таких полях стоит «Нет данных», а проверки не объявляют место закрытым без оснований.
- **Стоимость, риск и расстояния** — оценки проекта по заданным правилам, а не подтверждённые факты о реальной поездке.

## Откуда берутся данные

| Данные | Источник | Ключ | Статус |
|---|---|---|---|
| Координаты городов | OpenStreetMap / Nominatim | нет | реальные данные, лимит 1 запрос/с |
| Места и достопримечательности | Wikipedia GeoSearch (10 км вокруг центра) | нет | реальные названия и координаты |
| Погода | Open-Meteo (forecast и archive) | нет | прогноз до ~16 дней, дальше — архив прошлого года |
| Курсы валют | ЦБ РФ, XML | нет | реальные курсы, кэш на сессию |
| Авиабилеты | travel-search-ru → кэш Aviasales | нет | кэш до 48 ч, только самый дешёвый вариант |
| Поезда | travel-search-ru → кэш Tutu.ru | нет | только внутри страны, цена ориентировочная |
| Отели | travel-search-ru → Level.Travel / Travelata | нет | цена за всё проживание, предложение живёт ~20 мин |
| Ссылка на отели | Trip.com (из ответа travel-search-ru) | нет | ссылка на поиск, не бронирование |
| Авиабилеты и отели (запасной вариант) | Travelpayouts / Aviasales, Hotellook | `TRAVELPAYOUTS_TOKEN` | кэш цен, используется если travel-search-ru не дал данных |
| Поезда и автобусы (оценка) | оценка проекта по расстоянию | — | `estimate`, если реальных данных нет |

Без ключей приложение полностью работает: транспорт и проживание берутся из travel-search-ru либо считаются как помеченные оценки. Токен Travelpayouts не обязателен и нужен только как запасной источник кэшированных цен.

### travel-search-ru: сторонний сервис

Поисковый слой — открытый проект **travel-search-ru** (<https://github.com/MissiaL/travel-search-ru>), автор **MissiaL**, лицензия MIT. Это не код OneTrip: проект использует его как внешний MCP-сервис по адресу `https://mcp.botclaw.ru/travel`. Ссылки ведут на страницы поиска, а не на оформление и оплату брони.

- Сервис доступен без авторизации и возвращает данные в формате MCP Streamable HTTP (SSE).
- Приложение только читает данные и не выполняет бронирование.
- Цены и расписания кэшированные; сервис сам сообщает об этом в примечаниях, и эти примечания показываются в плане.
- Отключить интеграцию можно переменной `TRAVEL_SEARCH=0` — тогда останутся Travelpayouts и оценки проекта.

## Что умеет MVP

- Разбор естественного языка: города, даты или период, длительность, бюджет, интересы, пожелания к отелю, «что не нравится».
- **Фокус на Россию**: пять городов на первом экране и подсказки про поезд для расстояний 300–1200 км; в режиме `live` работает любой город, который находится через Nominatim.
- **Выбор формата жилья** в мастере: отель, гостевой дом, хостел, апартаменты, кемпинг/глэмпинг или необычное жильё. Формат влияет на ранжирование, но не скрывает найденные варианты; если источник не подтвердил пожелание, план честно об этом сообщает.
- Необязательная **бесплатная облачная языковая модель по API-ключу** (Gemini, Groq или OpenRouter): понимает любые города, опечатки и формулировки вроде «вернуться через три ночи». Ключ хранится только в локальном `.env`.
- Работа без языковой модели: запасной разбор по правилам.
- **Мультимодальный транспорт**: самолёт, поезд и автобус; пары «туда + обратно» одного вида транспорта, без смешивания.
- **Сравнение сервисов**: минимальные цены Aviasales/travel-search-ru, Travelpayouts и Tutu.ru по каждому направлению; одинаковые рейсы объединяются, остаётся меньшая цена.
- **Дорога до отеля**: пешком, общественный транспорт и такси — оценки проекта по расстоянию, ссылки на маршрут в OpenStreetMap и Яндекс Картах; в смете учитывается дорога до узла и поездка отель ↔ аэропорт/вокзал.
- Детерминированное ранжирование вариантов по весам из `data/assumptions.json`.
- Маршрут по дням: до 4 мест в день, время посещения, дорога от отеля, прилёт и вылет, ограничение пешей нагрузки.
- Расчёт стоимости: транспорт туда и обратно, багаж, проживание, туристический налог, трансферы, местный транспорт, билеты.
- Reality Check: 12 кодов проблем, уровни «низкий / средний / высокий», очки риска, русские описания и рекомендации.
- Честная защита от выдуманного плана: если у провайдера нет данных о городе, стоимость и маршрут не показываются, а план помечается высоким риском.
- Цикл автоматических исправлений: до 3 попыток, строгое улучшение, без ложных заявлений об успехе.
- Streamlit-интерфейс: пошаговый мастер из пяти шагов, отдельный экран результатов с вкладками, свободный запрос, уточняющий вопрос, исходный и итоговый план, скачивание Markdown.
- Оценка качества на 5 сценариях с тестовыми фикстурами (`evaluate.py`), включая JSON-вывод.
- 268 тестов без обращения к сети.

## Архитектура

```text
Запрос пользователя
        │
        ▼
agent/parser.py ──► TripRequest
        │
        ▼
providers/ (live + тестовые фикстуры) ──► транспорт, отель, места, погода
        │
        ▼
agent/planner.py ──► ранжирование + маршрут + стоимость
        │
        ▼
checks/ ──► Reality Check (детерминированные правила)
        │
        ▼
agent/corrector.py ──► исправления и повторная проверка (до 3 попыток)
        │
        ├──► app.py       Streamlit-интерфейс и Markdown-отчёт
        └──► evaluate.py  оценка сценариев
```

Языковая модель используется **только для разбора запроса**. Проверки, ранжирование, расчёт стоимости и исправления не зависят от модели и всегда дают одинаковый результат при одинаковых данных и настройках.

## Установка и запуск на Windows

Самый простой способ — **двойной щелчок по `start.bat`** в папке проекта. Файл сам:

1. выберет `.venv\Scripts\python.exe`, если виртуальное окружение уже создано, иначе обычный `python`;
2. запустит `start.py`;
3. `start.py` проверит наличие `app.py` и недостающих зависимостей (при необходимости предложит установить их из `requirements.txt`);
4. запустит Streamlit и откроет браузер.

Если что-то не работает, запустите вручную из PowerShell:

```powershell
# 1. Создать виртуальное окружение
python -m venv .venv

# 2. Активировать его
.venv\Scripts\Activate.ps1
# Если PowerShell запрещает запуск скриптов, выполните один раз:
# Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Создать файл настроек
copy .env.example .env

# 5. Запустить интерфейс
streamlit run app.py
```

Или без активации окружения: `python start.py` (работает и на Linux/macOS).

После запуска Streamlit откройте адрес, который он покажет в терминале (обычно `http://localhost:8501`).

Требуется Python 3.11 или новее (`python --version`).

### Источники данных

Отдельного демонстрационного режима нет: приложение всегда работает с открытыми источниками и помеченными оценками. Переменная `DATA_PROVIDER` оставлена для совместимости:

```text
DATA_PROVIDER=live
```

После изменения `.env` перезапустите Streamlit: настройки читаются при старте.

- **`live`** — работает для любого города, который находится через Nominatim. Без ключей даёт реальные места, погоду и координаты, а также транспорт и отели из travel-search-ru; остальное — помеченные оценки.
- Любое другое значение не включает вымышленные данные: приложение сообщает в пояснениях, что режим не поддерживается, и продолжает работать на `live`.

### Сервис поиска travel-search-ru

Интеграция включена по умолчанию и не требует ключа. Отключение:

```text
TRAVEL_SEARCH=0
```

Тогда приложение использует Travelpayouts (если задан токен) и оценки проекта. Значения `false`, `no`, `off` также выключают сервис.

Сервис сторонний и лицензирован по MIT (автор — MissiaL). Приложение не бронирует билеты и отели, а только показывает найденные варианты и ссылки на поиск. Кэш и ориентировочные цены всегда подписаны в карточках и в отчёте.

### Токен Travelpayouts (необязательно)

Токен включает запасной источник кэшированных цен на самолёты и отели — на случай, если travel-search-ru не ответил:

1. Зарегистрируйтесь на <https://www.travelpayouts.com/>.
2. Возьмите API-токен в личном кабинете (раздел API).
3. Впишите его в локальный `.env`:

```text
TRAVELPAYOUTS_TOKEN=ваш-токен
```

4. Перезапустите Streamlit. В подвале страницы появится статус токена.

Токен — секрет: не коммитьте `.env` и не вставляйте токен в README, `.env.example`, скриншоты или чат. Без токена приложение продолжает работать: travel-search-ru и оценки проекта остаются доступны.

### Быстрая проверка без интерфейса

```powershell
python evaluate.py
python evaluate.py --json
python evaluate.py --scenario baseline
```

`evaluate.py` использует тестовый провайдер фикстур и фиксированную дату оценки, чтобы результат был воспроизводимым. Код возврата `0` означает, что все сценарии совпали с ожиданиями, `1` — что какая-то проверка не прошла. Фикстуры лежат в `fixtures/` и не участвуют в работе интерфейса.

## Настройка языковой модели (бесплатная облачная, по ключу)

Без модели парсер работает по правилам: он понимает только города из словаря `CITY_PATTERNS`. Для произвольных городов, опечаток и сложных формулировок подключите бесплатную облачную модель. Локальная модель для проверки судьями не нужна.

**Рекомендуемый вариант — Google AI Studio (Gemini, бесплатный тариф):**

1. Получите бесплатный ключ: <https://aistudio.google.com/apikey>.
2. Убедитесь, что в папке проекта есть `.env`. Если его нет (например, после клонирования с GitHub), скопируйте `.env.example` в `.env`.
3. Заполните `LLM_MODEL` и `LLM_API_KEY`. Рекомендуемая модель — `gemini-3.5-flash-lite`: она бесплатна на тарифе Gemini и отвечает за 1–2 секунды. Адрес Gemini в локальном `.env` уже прописан:

```text
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_MODEL=gemini-3.5-flash-lite
LLM_API_KEY=ваш-ключ
LLM_TIMEOUT_SECONDS=60
```

Google периодически снимает старые модели с поддержки (например, `gemini-2.5-flash` уже недоступна новым пользователям). Если вместо ответа появляется «сервис модели вернул ошибку (код 404)», возьмите актуальное имя Flash/Lite-модели на <https://ai.google.dev/gemini-api/docs/models>. Полноразмерные Flash-модели отвечают заметно медленнее (до 50–75 секунд), поэтому для быстрой проверки лучше Lite.

4. Перезапустите Streamlit: `load_dotenv()` читает `.env` только при старте приложения. В подвале страницы появится «LLM: настроена (<модель>)».

**Альтернативы с бесплатным тарифом** (подойдёт любой OpenAI-совместимый `/chat/completions`):

```text
# Groq
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=имя-модели-из-консоли-Groq

# OpenRouter, модель с пометкой :free
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=имя-модели:free
```

Если модель недоступна, превысила лимит или вернула некорректный ответ, приложение сообщает об этом и продолжает работать по правилам.

### Для судей и проверки с GitHub

- `.env` **не входит в репозиторий** (исключён в `.gitignore`), поэтому чужие ключи не публикуются.
- Без ключей приложение запускается сразу: `DATA_PROVIDER=live` работает на открытых данных и помеченных оценках.
- Разбор произвольного города по правилам ограничен словарём. Чтобы проверить редкий город, судья вставляет **свой** бесплатный ключ модели в локальный `.env`.
- Реальные кэшированные цены включаются только после добавления **своего** токена Travelpayouts. Без него цены транспорта и отеля честно подписаны как оценка проекта.
- Никогда не коммитьте `.env` и не вставляйте ключи в `.env.example`, README или скриншоты.

## Как работает парсер

1. Правила находят города (из словаря), длительность, даты, бюджет, интересы и «что не нравится». Числа понимаются и цифрами, и словами: «через три ночи» = 4 дня.
2. Если модель настроена, она разбирает запрос целиком, включая редкие города и опечатки, а недостающее добирается из результата правил. Города возвращаются в именительном падеже; неизвестный город не подменяется похожим известным.
3. Результат проверяется Pydantic: некорректные поля отбрасываются с пояснением.
4. Если не хватает города вылета, назначения или длительности, задаётся **один** уточняющий вопрос на русском; ответ объединяется с прежним запросом.

## Как собирается план

1. Провайдер всегда `live`: открытые источники, travel-search-ru и помеченные оценки. Неизвестное значение `DATA_PROVIDER` откатывается на `live` с пояснением.
2. Даты берутся из запроса. Если указан только период («середина ноября»), используется приблизительная дата, а затем — даты выбранного транспорта. Все допущения попадают в пояснения.
3. Транспорт строится в обе стороны. Оцениваются три варианта — самолёт, поезд и автобус. Если travel-search-ru вернул авиабилеты, оценка самолёта убирается; для маршрута внутри одной страны добавляются реальные поезда Tutu.ru, и оценка поезда убирается. Поезд и автобус остаются для сравнения. Пара «туда + обратно» всегда одного вида транспорта, обратный рейс вылетает после прилёта туда. Предложения Aviasales через travel-search-ru и Travelpayouts объединяются: рейс с одинаковым номером, временем и пересадками считается дублем, в план попадает меньшая цена, а число совпадений фиксируется в пояснениях.
4. Варианты ранжируются по цене, времени в пути и числу пересадок; отель и места — по весам из `data/assumptions.json`.
5. Маршрут распределяет места по дням с учётом времени посещения, дороги от отеля, прилёта и вылета. День длится с 09:00 до 19:00, после прилёта резервируется буфер 120 минут.
6. Стоимость складывается из транспорта туда и обратно, багажа, проживания, туристического налога, трансферов, местного транспорта и билетов. Это оценка, а не подтверждённые цены.
7. Уже при сборке запускается Reality Check, поэтому `issues` и `risk_score` заполнены сразу.

### Как оцениваются поезд и автобус

Бесплатного API РЖД нет, поэтому используются настраиваемые допущения из `data/assumptions.json`:

| Вид | Скорость | Цена | Наземное время | Ограничение |
|---|---|---|---|---|
| Самолёт | 750 км/ч | 2 500 ₽ + 4,5 ₽/км | +120 мин | до 12 000 км |
| Поезд | 70 км/ч | 1 200 ₽ + 2,2 ₽/км | +45 мин | до 8 000 км |
| Автобус | 55 км/ч | 500 ₽ + 1,8 ₽/км | +30 мин | до 1 500 км |

Это **не тарифы перевозчиков**, а оценка проекта: она позволяет сравнить виды транспорта и посчитать бюджет, но не заменяет покупку билета. Время отправления и прибытия — местное, часовые пояса не учитываются.

### Сравнение предложений разных сервисов

В режиме `live` провайдер может получить рейсы из двух источников: travel-search-ru (кэш Aviasales) и Travelpayouts, если задан токен. Дубли определяются по виду транспорта, номеру рейса, времени вылета и числу пересадок; из пары остаётся предложение с меньшей ценой. В план попадает сводка `price_sources`: сервис, направление, вид транспорта, минимальная цена, число предложений и тип цены. Сводка показывает только то, что реально вернули источники, и не подтверждает наличие мест. Сравнение не учитывает багаж и условия возврата — перед покупкой тариф нужно проверить на сайте сервиса. Приложение не бронирует билеты и не обходит ограничения сайтов.

### Дорога до отеля

Если у рейса есть координаты узла из OpenStreetMap (аэропорт, вокзал или автостанция), planner считает расстояние до выбранного отеля и добавляет три варианта:

| Вариант | Когда показывается | Как считается |
|---|---|---|
| Пешком | до 2 км | 0 ₽, скорость 4,5 км/ч |
| Общественный транспорт | от 1–2 км | 80 ₽ + 6 ₽/км, 18 км/ч, ожидание и пересадки +20 мин |
| Такси | всегда | 200 ₽ + 35 ₽/км, 40 км/ч, подача 5 мин |

Это **оценки проекта по расстоянию**, а не тариф Яндекс Такси и не расписание транспорта. Для каждого варианта есть ссылка на маршрут в OpenStreetMap, для всех трёх — в Яндекс Картах; поездку в такси пользователь заказывает сам в приложении Яндекс Go. Блок «Дорога до отеля» находится на вкладке «Отели», а стоимость поездки отель ↔ узел входит в статью «Трансферы» (при наличии координат). Пороги и цены настраиваются в `data/assumptions.json` → `access_estimates`.

## Reality Check: правила и коды

Проверки находятся в `checks/`, не используют языковую модель и работают по порогам из `data/assumptions.json`.

| Код | Уровень | Когда срабатывает |
|---|---|---|
| `LATE_ARRIVAL` | высокая | прилёт в окно 00:00–05:00 (настраивается) |
| `SHORT_LAYOVER` | высокая | пересадка короче 60 мин внутренней или 120 мин международной |
| `HOTEL_FAR_FROM_CENTER` | средняя | отель дальше 40 минут от центра |
| `HOTEL_FAR_FROM_METRO` | средняя | отель дальше 15 минут от метро |
| `PLACE_CLOSED` | высокая | место запланировано в закрытый день |
| `OPENING_HOURS_CONFLICT` | средняя | посещение выходит за часы работы |
| `DAY_OVERLOADED` | средняя | больше 15 км пешком или больше 5 мест в день |
| `WEATHER_CONFLICT` | средняя | плохая погода и уличные места в этот день |
| `BUDGET_EXCEEDED` | высокая / средняя | перерасход больше 20% — высокая, иначе средняя |
| `COST_MISSING` | высокая | стоимость не рассчитана или равна нулю |
| `COST_INCOMPLETE` | средняя | в плане нет пары рейсов или отеля |
| `DESTINATION_UNSUPPORTED` | высокая | у провайдера нет ни рейсов, ни отелей, ни мест, ни погоды для города |

У каждой проблемы есть `code`, `severity`, русское `description`, `source` и русская `recommendation`. Если часы работы неизвестны, проверка не объявляет место закрытым, а добавляет пояснение «Нет данных».

### Оценка риска

Очки задаются в `data/assumptions.json`:

- низкая проблема — 1 очко;
- средняя — 3 очка;
- высокая — 6 очков.

Уровень «средний» начинается с 3 очков, «высокий» — с 7. Это эвристика проекта, а не научно проверенная вероятность.

Если сработал `DESTINATION_UNSUPPORTED`, уровень риска всегда «высокий»: при отсутствии данных поездку нельзя оценить остальными правилами. Стоимость и маршрут в этом случае не рассчитываются, чтобы не выдавать вымышленные числа за план.

## Автоматические исправления

`agent/corrector.py` строит альтернативные варианты и применяет только тот, который строго улучшает пару «риск → число проблем → стоимость»:

- другая пара транспорта при ночном прилёте, короткой пересадке или перерасходе;
- другой отель при удалённости от центра/метро;
- исключение мест с нарушением часов работы;
- приоритет помещений в дождливые дни;
- ограничение числа мест и пешей нагрузки при перегрузке дня.

Цикл ограничен `max_correction_attempts` (по умолчанию 3). План не может «исправиться» до пустого маршрута или потерять транспорт/отель. Если улучшить план одним шагом нельзя, агент честно пишет, что остались нерешённые проблемы, и не объявляет поездку безопасной. Сценарий `history` в `evaluate.py` специально демонстрирует такой честный отказ.

## Интерфейс

`app.py` запускает Streamlit-приложение. Планирование идёт **по пяти шагам**, без формы «всё сразу»:

1. **Маршрут.** Города отправления и назначения вводятся текстом в поля «Откуда» и «Куда»; значение сохраняется по кнопке «Продолжить» или Enter, даже если поле не было подтверждено отдельно. Ниже — карточки популярных направлений с локальными фотографиями и ссылками на Википедию и кнопка «Убрать направление». Честно указано, что поездка в одну сторону и несколько городов движком пока не поддерживаются.
2. **Даты.** Начало и конец поездки, число дней и ночей, ограничение 30 днями. Гибкие даты и «плюс-минус несколько дней» недоступны: поиску нужны точные даты.
3. **Путешественники.** Взрослые и дети, общее число. В поиск отелей передаётся только число взрослых; детские тарифы источники не принимают, поэтому цены не умножаются на число людей.
4. **Бюджет и стиль.** Бюджет и валюта, признак «на всю группу / на человека», предпочтение транспорта, стиль проживания, темп поездки, интересы, «чего избегать» и необязательное свободное описание. «Экономнее/Комфортнее» — пожелание к ранжированию отелей, а не скрывающий варианты фильтр.
5. **Проверка.** Сводка маршрута, дат, путешественников и бюджета; каждую секцию можно изменить отдельно, не теряя остальные ответы. Поиск запускается только кнопкой «Найти варианты и составить план».

Между шагами работают «Назад» и «Продолжить», прогресс показывает реальный номер шага. Ответы сохраняются при переходах и перерисовках, а переключение шагов не запускает повторный поиск. Проверка шага выполняется по нажатию кнопки, поэтому кнопки не блокируются до подтверждения полей: при ошибке показывается понятное сообщение на русском и шаг не меняется.

Оформление — светлая современная travel-tech тема: фон `#F8FAFC`, основной синий `#2563EB`, тёмный текст `#0F172A`, бирюзовый акцент `#14B8A6` для положительных результатов и выполненных шагов. Шрифт — Inter (с запасными системными шрифтами), крупные заголовки с плотным межбуквенным интервалом. Первый экран — иллюстрированная векторная сцена (закат, горы и озеро, файл `static/hero_scene.svg`) с медленно плывущими облаками, заголовок «Путешествуй умнее. Трать меньше.» по центру и кнопка «Спланировать поездку», которая прокручивает к мастеру. Карточка мастера «парит» над нижним краем сцены; блок «Reality Check» вынесен под форму. Мастер, карточки направлений, метрики и вкладки результатов — белые скруглённые карточки с мягкими тенями; активный шаг и выбранная вкладка залиты синим, выполненные шаги — бирюзовым. Предупреждения разделены по цвету: информация — синий, успех — бирюзовый, предупреждение — янтарный, ошибка — красный. Верхняя панель содержит название и навигацию по разделам страницы («Планировщик», «Reality Check», «Направления», «Быстрые действия»), а на экране результатов — кнопку «Новый запрос». Тестовые действия «Подставить пример» и «Очистить результат» вынесены в раскрывающийся блок «Быстрые действия» в подвале. Тема задаётся в `.streamlit/config.toml` (`base = "light"`), а цвета, типографика и анимации — в блоке CSS внутри `app.py` (переменные `--ot-*` в начале блока). Иллюстрация первого экрана лежит в `static/hero_scene.svg` и отдаётся через `enableStaticServing = true` по пути `/app/static/hero_scene.svg`. Контраст основных пар цветов проверен расчётом (не ниже 4,5:1 для текста); при системной настройке «уменьшить движение» анимации отключаются.

После поиска открывается отдельный экран результатов:

- заголовок маршрута, даты, число путешественников, темп, риск и остаток бюджета;
- метрики оценки стоимости, бюджета, числа проблем и исправлений;
- кнопки «Изменить параметры», «Повторить поиск», «Скачать план в Markdown»;
- вкладки **«Обзор», «Транспорт», «Отели», «Бюджет», «Об источниках»**;
- карточки транспорта: вид, перевозчик, время, длительность, цена, источник и ссылка на предложение; сравнение всех найденных вариантов, включая дорогие, без субъективной рекомендации;
- блок «Сравнение сервисов»: минимальная цена каждого ответившего сервиса по направлениям «туда» и «обратно», тип цены и число предложений; кнопка «Выбрать этот вариант» фиксирует выбранную пару рейсов при пересборке плана;
- карточки отелей: название, район, цена за всё проживание и за ночь, рейтинг, питание, расстояния или «нет данных», источник, ссылка на предложение и ограничения;
- блок «Дорога до отеля»: пешком, общественный транспорт и такси с оценкой времени и цены, ссылками на маршруты в OpenStreetMap и Яндекс Картах и честной пометкой, что тариф и расписание не проверены;
- бюджет: известные статьи, итог, остаток и явный список категорий, которые не оценены (не считаются нулём);
- источники: назначение каждого сервиса, атрибуция travel-search-ru (MissiaL, MIT), OpenStreetMap, Open-Meteo, Wikipedia/Wikimedia Commons и Travelpayouts, а также пояснения к данным;
- исходный план до исправлений и журнал изменений.

Свободное поле запроса остаётся альтернативой мастеру, а «Подставить пример» в блоке «Быстрые действия» в подвале заполняет его демонстрационным текстом. Если не хватает города или длительности, приложение задаёт уточняющий вопрос. Фотографии направлений лежат в `assets/destinations` и показываются локально; ссылки на карточках ведут на статьи Википедии, атрибуция Wikimedia Commons указана на вкладке «Об источниках».

## Оценка сценариев на тестовых фикстурах

`evaluate.py` прогоняет полный цикл на пяти сценариях:

| Сценарий | Что показывает |
|---|---|
| `baseline` | ночной прилёт, закрытое место, перегрузка, часы работы, дождь → риск снижается |
| `low_budget` | бюджет 30 000 ₽: перерасход остаётся и честно показывается |
| `far_hotel` | пожелание «хостел» приводит к далёкому отелю, затем отель меняется |
| `relative_dates` | примерные даты «середина ноября» и пояснение допущения |
| `history` | доступные замены не улучшают план одним шагом — агент не притворяется |

Для каждого сценария проверяются ожидаемые коды проблем до и после, динамика риска, лимит попыток, полнота плана и честность итоговых формулировок.

## Запуск тестов

```powershell
python -m pytest -v
```

Тесты не обращаются к сети: провайдер фикстур читает локальные JSON-файлы из `fixtures/`, адаптеры Travelpayouts, travel-search-ru, геоданных и погоды проверяются на поддельных HTTP-ответах, вызовы LLM подменяются. Общая фикстура `tests/conftest.py` подменяет `get_provider` в планировщике и корректоре на `FixtureProvider` и выключает `TRAVEL_SEARCH`, поэтому локальный `.env` не влияет на результат. В набор входят:

- модели и тестовые фикстуры;
- парсер и `llm.py`;
- провайдеры, мультимодальные оценки и ранжирование;
- адаптеры Travelpayouts, геокодинга, погоды и мест;
- клиент travel-search-ru: MCP-рукопожатие, SSE, UTF-8 без charset, ошибки, кэш и преобразование рейсов, поездов и отелей;
- интеграция travel-search-ru в live-провайдер, выбор поездов только внутри страны и запасной путь через Travelpayouts;
- объединение дублей рейсов из двух сервисов и сохранение меньшей цены;
- оценка дороги до отеля: пешком, общественный транспорт, такси, ссылки на карты;
- маршрут и стоимость;
- все правила Reality Check;
- цикл исправлений и интеграционный сценарий;
- Markdown-отчёт;
- Streamlit-интерфейс через `streamlit.testing.v1.AppTest`: все пять шагов мастера, переходы назад и вперёд, сохранение ответов, валидация дат, экран результатов, вкладки, изменение параметров, повторный поиск, отсутствие поиска при переключении шагов, выбор варианта транспорта и выбор отеля с пересборкой плана;
- `evaluate.py`.

## Ограничения текущей версии

- **Цены и расписания travel-search-ru — кэш, а не поиск в реальном времени.** Авиабилеты Aviasales могут отставать до 48 часов и содержат только самый дешёвый вариант на дату; поезда Tutu.ru — кэш расписания с ориентировочной ценой; предложения отелей Level.Travel/Travelata живут около 20 минут и могут измениться. Приложение подписывает это в карточках, в отчёте и в примечаниях сервиса.
- **Сервис travel-search-ru сторонний.** Он доступен по сети и может быть недоступен или ограничить частоту запросов; в этом случае приложение честно сообщает об ошибке и переходит к Travelpayouts или оценкам.
- **Цены Travelpayouts (запасной источник) — тоже кэш.** Они могут быть устаревшими или относиться к соседним датам.
- **Дорога до отеля — оценка по расстоянию.** Такси и общественный транспорт считаются по прямым координатам и тарифам из `assumptions.json`, а не по API Яндекс Такси или расписанию перевозчика. Пробки, подача, остановки и пересадки не проверяются; ссылки ведут на карту, а не оформляют заказ. Если у рейса нет координат узла, блок не показывается.
- **Багаж.** Источник не сообщает, включён ли багаж, поэтому поле подписано «источник не сообщил», а не «не включён».
- **Отели без данных travel-search-ru и без токена** — оценка проекта с рейтингом «нет данных». С токеном используется кэш Hotellook; часть рейтингов оценивается по числу звёзд и подписывается.
- **Расстояния отеля до центра и метро известны не всегда.** Если сервис их не сообщил, показывается «нет данных», отель не получает преимущество в ранжировании, а проверки не создают ложную проблему.
- **Поезда запрашиваются только внутри одной страны.** Для зарубежных маршрутов Tutu.ru не используется; поезд и автобус остаются оценкой проекта.
- **Реального API РЖД нет.** Автобусы и поезда вне покрытия Tutu.ru — оценка по расстоянию, а не расписание и тарифы перевозчика.
- **Места из Wikipedia** не содержат часов работы, рейтинга и стоимости входа; эти поля помечены «Нет данных».
- **Погода дальше ~16 дней** — архив прошлого года, а не прогноз. Осадки для архива не показываются.
- **Маршрут — один город назначения.** Поездка в одну сторону, несколько городов и гибкие даты («плюс-минус несколько дней») движком не поддерживаются; мастер сообщает об этом, а не имитирует такие сценарии.
- **Детские тарифы не поддерживаются.** Число детей сохраняется в запросе и показывается в сводке, но источники не принимают возраст, поэтому цены не пересчитываются на детей.
- **Фотографии направлений — иллюстрации Wikimedia Commons**, сохранённые локально. Они не подтверждают доступность города, отеля или билетов.
- Тестовые фикстуры (`fixtures/`) содержат вымышленные данные Стамбула и используются только в pytest и `evaluate.py`; интерфейс их не показывает.
- Итоговый риск — эвристика проекта, а не научно проверенная вероятность.
- Стоимость — оценка по допущениям проекта, а не подтверждённые цены.
- Разбор по правилам знает ограниченный список городов (`CITY_PATTERNS` в `agent/parser.py`); остальные города надёжно распознаёт модель либо ответ на уточняющий вопрос.
- Числовые даты вида `14.11` пока не распознаются; понимаются «14 ноября» и «с 14 по 17 ноября».
- «Через три ночи» считается от даты выезда как 3 ночи = 4 дня. Если дата выезда не названа, берётся текущая дата и это попадает в пояснения.
- «N ночей» считаются как N + 1 день.
- Время в пути — местное, без учёта часовых поясов.
- Часы работы через полночь не поддерживаются.
- Расстояния и пешая нагрузка — оценки по координатам и условной скорости, а не маршруты реального навигатора.
- Карта и PDF-экспорт не входят в текущую версию; отчёт выгружается в Markdown.
- Цикл исправлений жадный: он выбирает лучший шаг из доступных и может не найти улучшение, требующее двух шагов. Это ограничение показывается честно, а не скрывается.

## Публикация в Streamlit Community Cloud

Публичная копия работает без установки Python: приложение собирается из репозитория на GitHub.

1. Войдите на <https://share.streamlit.io> под своим аккаунтом GitHub.
2. Откройте готовую форму развёртывания: <https://share.streamlit.io/deploy?repository=gritsienkoartem/onetrip-reality-check&branch=main&mainModule=app.py>.
3. Проверьте поля: репозиторий `gritsienkoartem/onetrip-reality-check`, ветка `main`, главный файл `app.py`. Нажмите **Deploy**.
4. Ключи добавьте в **Settings → Secrets** уже созданного приложения — в формате `KEY = "value"` по одной строке, значения берите из локального `.env`:

```toml
LLM_BASE_URL = "https://..."
LLM_MODEL = "..."
LLM_API_KEY = "..."
LLM_TIMEOUT_SECONDS = "30"
TRAVELPAYOUTS_TOKEN = "..."
```

Секреты хранятся только в настройках Streamlit Cloud: не коммитьте их, не вставляйте в README и не присылайте в чат. Приложение читает их через `st.secrets` и переносит в переменные окружения при старте. Без ключей сайт тоже работает: разбор запроса идёт по правилам, данные берутся из открытых источников.

Бесплатный тариф засыпает без посетителей, поэтому первая загрузка после паузы занимает 30–60 секунд. Это не ошибка: дождитесь появления интерфейса или обновите страницу.

## Безопасность и GitHub

- `.env` и файлы с ключами исключены через `.gitignore`; никогда не коммитьте секреты.
- `.env.example` содержит только пустые переменные и комментарии.
- Мок-данные и оценки всегда помечаются; приложение не выдаёт их за реальные.
- Приложение не скрапит Aviasales, РЖД и другие сайты и не обходит защиту.
- travel-search-ru — сторонний проект MissiaL под лицензией MIT; приложение использует его как внешний сервис и не выдаёт за собственный код.
- Приложение только показывает варианты и ссылки на поиск; оплата и бронирование не выполняются.
- Перед публикацией проверьте `git status` и убедитесь, что в коммит не попали `.env`, токены и локальные файлы.
